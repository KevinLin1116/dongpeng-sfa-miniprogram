# 任务项执行本地端到端测试矩阵

本矩阵以正确在线结构中的 `06_任务执行`（父执行）和 `16_任务项执行`（逐任务项执行）为准。测试不得调用真实企业微信接口，也不得写在线智能表格。

## 测试分层

1. **纯计划层**：输入发布记录、门店、人员、任务项配置，验证 N 个执行对象与 M 个任务项的快照和唯一键。
2. **智能表格模拟层**：使用内存 Smart Sheet client，验证 06、16、结果表、07 的新增/更新次数、关联值和状态。
3. **处理器流程层**：使用内存数据库和依赖注入的 Smart Sheet client，执行发布、保存、提交、驳回、重提、通过全流程。

当前生产代码已提供 16 计划/幂等模块，并已把保存、完成、提交、驳回、通过写回接入 `index.js`。纯模块和适配器测试覆盖记录生成、字段契约及状态转换；`approval-resilience.test.js` 通过模块替换与内存数据库执行真实 handler，覆盖权限、生产禁用模拟数据、整改轮次、并发抢占、失败后人工对账和审批汇总保护。线上关联属性与真实企业微信链路仍须另行验证。

## 补齐真实本地端到端测试所需的最小接口

- `appendApprovalHistory({ client, taskItemExecutionRecordId, action, ... })`。
- `createWorkflowHandlers({ db, smartSheet, cloud, clock })`，返回发布、保存、提交和审批 handlers。
- 16 和 07 的写入函数必须接受模拟 client，禁止在模块内部新建真实客户端。

## 验收门槛

- 全部场景无需网络、Secret 或在线表格即可运行。
- 每个用例同时断言记录数量、唯一键、关联字段和值级状态。
- 重复执行同一用例，内存中的 06、16、07 和结果记录数量不增加。
- 新增 16 后，现有 06 字段、状态文案及保存人/提交人写回保持兼容。
- 标记为“阻塞”的场景在生产接口落地前不得报告为通过。
